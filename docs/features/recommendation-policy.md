# 추천 정책 가이드

이 문서는 옷장난감 추천 기능에서 사용하는 사용자 취향 점수, 추천 피드백, 추천 제외, 동점 처리 기준을 정리합니다. FE/BE 모두 추천 결과와 사용자 행동을 같은 의미로 이해하기 위해 이 문서를 기준으로 봅니다.

추천 기능의 요구사항 ID와 세부기능 ID는 [요구사항 정의서](../requirements/requirements-definition.md)를 원본으로 봅니다.

## 문서 위치 기준

- BE 레포: 추천 정책 원본 문서입니다.
- FE 레포: 동일본을 둡니다.
- FE 전용 화면 문구, 버튼 상태, 로딩/에러/빈 상태는 FE 문서에서 상세화합니다.

## 사용자 스타일 점수

사용자 스타일 점수는 `USER_STYLES`에 스타일별 row로 누적합니다.

| 컬럼 | 의미 |
| --- | --- |
| `preference_weight` | 온보딩/마이페이지에서 사용자가 선택한 스타일 점수 |
| `wardrobe_weight` | 사용자가 옷장에 등록한 옷 스타일 기반 점수 |
| `feedback_weight` | 추천 싫어요/추천 제외 기반 마이너스 점수 |
| `combined_weight` | 세 점수를 결합한 최종 스타일 점수 (온보딩 30% + 옷장 70% + 피드백) |

최종 점수는 아래 기준으로 계산하며, 사용자의 옷장 데이터 보유 여부를 기준으로 전략을 선택합니다.

- **신규 사용자 (옷장 비어있음)**:
  `combined_weight = preference_weight + feedback_weight`
- **기존 사용자 (옷장 데이터 있음)**:
  `combined_weight = round(preference_weight * 0.3 + wardrobe_weight * 0.7) + feedback_weight`

> **판단 기준**: 사용자가 소유 중인(`OWNED`) 옷장 아이템이 1개 이상 존재하면 '기존 사용자'로 간주합니다. 특정 스타일의 `wardrobe_weight`가 0이더라도, 전체 옷장에 데이터가 있다면 30/70 결합 전략을 유지합니다.

## 점수 부여 기준

| 대상 | 대표 스타일 | 보조 스타일 |
| --- | --- | --- |
| 온보딩/마이페이지 선호 스타일 선택 | +7 | +3 |
| 옷장 등록 옷 스타일 | +7 | +3 |
| 추천 싫어요 | -7 | -3 |
| 추천 제외 | -7 | -3 |

온보딩 또는 마이페이지에서 여러 스타일을 선택하면 첫 번째 선택을 대표 스타일, 나머지를 보조 스타일로 봅니다.

## 색상 점수

옷 색상도 대표/보조 개념을 사용합니다.

| 대상 | 대표 색상 | 보조 색상 |
| --- | --- | --- |
| 옷 색상 | 7 | 3 |

색상과 스타일은 서비스에서 지정한 카탈로그 값 안에서 선택합니다. 중복 없이 카탈로그 전체 범위까지 선택할 수 있으며, 현재 API validation 기준은 보조 색상 최대 12개, 스타일 최대 10개입니다.

## 추천 피드백

| 피드백 | 의미 | 점수 반영 | 추천 후보 처리 |
| --- | --- | --- | --- |
| 싫어요 | 사용자가 추천이 마음에 들지 않음을 표시 | 대표 -7, 보조 -3 | 이후 추천 점수에 비선호로 반영 |
| 추천 제외 | 사용자가 해당 옷/상품을 다시 보고 싶지 않음을 표시 | 대표 -7, 보조 -3 | 사용자 추천 후보에서 영구 제외 |

추천 피드백은 사용자별로 관리하며 다른 사용자 추천에는 영향을 주지 않습니다.

## 동점 처리

기본 정책: 추천 점수가 같은 후보는 같은 점수 그룹 안에서 랜덤 노출합니다.

**예외 — `RECO-004` 어울리는 옷 추천**: 같은 어울림 점수(`compatibilityScore`) 그룹 안에서는 `brandName`이 `UNKNOWN`이 아닌 후보를 먼저 노출합니다. 두 후보 모두 브랜드가 알려져 있거나 모두 `UNKNOWN`이면 조회 순서에 따릅니다.

이 정책은 같은 사용자에게도 같은 점수 후보의 순서가 매번 달라질 수 있음을 의미합니다(`RECO-004` 제외). FE는 같은 점수 후보의 순서 변경을 오류로 보지 않습니다.

## 유사 상품 추천 정책

`RECO-003` 유사 상품 추천은 기준 옷과 같은 카테고리의 내부 `EXTERNAL_SHOPPING` 공용 후보를 우선 사용합니다.

- 내부 후보는 기준 옷과의 아이템 타입, 대표/보조 색상, 대표/보조 스타일, 시즌, 디자인 키워드, 브랜드 유사도를 점수화해 높은 점수순으로 선별합니다.
- 최종 응답은 가능한 경우 내부 후보 8, 네이버쇼핑 후보 2 비율로 구성합니다.
- 내부 후보가 부족하면 네이버쇼핑 후보로 남은 슬롯을 보충할 수 있습니다.
- 사용자가 이미 `OWNED` 또는 `WISHLIST`로 등록한 옷과 추천 제외한 옷은 후보에서 제외합니다.

## AI MD 추천 정책

`RECO-005` AI MD 상품 추천은 내부 `EXTERNAL_SHOPPING` 공용 후보를 우선 사용합니다.

- 내부 상품 후보는 선택한 MD 성별과 `UNISEX` 상품만 사용합니다.
- 내부 상품은 MD 스타일 코드, 사용자 스타일 가중치, 사용자 옷장 색상과의 적합도를 점수화해 높은 점수순으로 Gemini 후보에 전달합니다.
- 네이버쇼핑 후보는 내부 상품으로 부족한 분위기나 카테고리를 보강할 때 사용합니다.
- AI MD 코디 추천은 보유 옷을 반드시 포함하지 않아도 됩니다.
- 코디 후보와 저장 요청은 옷장 등록 옷(`OWNED`, `WISHLIST`)과 외부/내부 추천 상품을 합쳐 `TOP`, `BOTTOM`, `SHOES`가 모두 포함되면 유효합니다.
- `wardrobeClothesIds`는 `null` 또는 빈 배열일 수 있으며, 외부/내부 추천 상품만으로 완성된 코디도 저장할 수 있습니다.
- 코디 구성은 보유 옷 포함 여부보다 색상 연결, 실루엣 균형, 소재감, 상황 적합성을 우선합니다.

## MVP 추천 범위

| 세부기능 ID | 추천 기능 | 설명 |
| --- | --- | --- |
| `RECO-001` | OOTD 코디 | 사용자 기준 코디 추천. 날씨, 계절, 온도는 보조 조건으로 반영 |
| `RECO-002` | 취향 분석/스타일 기반 추천 | 사용자 스타일 점수를 기반으로 상품 추천 |
| `RECO-003` | 유사 상품 추천 | 선택한 옷과 유사한 상품 추천 |
| `RECO-004` | 어울리는 옷 추천 | 사용자 옷장 데이터를 기준으로 함께 입기 좋은 상품 추천. `GET .../recommendations`의 `limitPerCategory` query는 기본 `5`, 허용 `1`~`50` |
| `RECO-005` | AI MD 추천 | 추천 이유와 스타일링 설명 생성 |
| `RECO-012`~`RECO-013` | 추천 싫어요/제외 | 추천 피드백과 제외 처리 |

날씨와 지역 정보(`EXT-003`~`EXT-004`)는 독립 추천 기능이 아니라 OOTD, 취향 기반 추천 등 추천 기능의 보조 조건으로 사용합니다.

## FE 확인 포인트

- 추천 제외는 단순 숨김이 아니라 영구 제외입니다.
- 싫어요와 추천 제외는 모두 사용자 스타일 점수에 마이너스 피드백으로 반영됩니다.
- 같은 점수 그룹 안에서는 랜덤 노출될 수 있습니다. `RECO-004` 어울리는 옷 추천은 동점 시 `UNKNOWN`이 아닌 브랜드를 우선합니다.
- 추천 결과에는 왜 추천되었는지 설명할 수 있는 텍스트가 필요할 수 있습니다.
- 추천 제외 또는 싫어요 이후 화면에서 즉시 제거할지, 다음 요청부터 제외할지는 FE/BE 연동 시 별도로 맞춥니다.

## BE 확인 포인트

- 사용자별 피드백만 반영하고 다른 사용자 추천에 영향을 주지 않습니다.
- 추천 제외된 옷은 해당 사용자의 추천 후보에서 제외합니다.
- 점수 계산 로직은 대표/보조 스타일 가중치를 지켜야 합니다.
- 점수 동점 그룹 랜덤 노출은 추천 품질을 해치지 않는 범위에서 수행합니다. `RECO-004`는 동점 시 `brandName != UNKNOWN` 우선 정렬을 적용합니다.
- `RECO-004` `limitPerCategory` query는 기본 `5`, 허용 범위 `1`~`50`입니다. 컨트롤러 validation과 [api-contract.md](../api/api-contract.md)를 동일하게 유지합니다.
