# 데이터 생명주기

이 문서는 BE 데이터 생성, 연결, 삭제, 보존 기준을 정리합니다. DB/ERD와 API 구현을 리뷰할 때 삭제 범위와 데이터 보존 정책을 확인하기 위한 BE 중심 문서입니다.

## 문서 위치 기준

- BE 레포: 원본 문서입니다.
- FE 레포: 전체 복사보다는 필요한 요약만 FE 문서에서 참조합니다.

## 핵심 원칙

- `CLOTHES`는 공통 옷 정보이므로 사용자 옷장 삭제와 함께 삭제하지 않습니다.
- `WARDROBE_CLOTHES`는 사용자 옷장과 공통 옷 정보의 연결입니다.
- 사용자 옷장에서 옷을 삭제하면 사용자 연결만 제거하거나 비활성화합니다.
- 이미지 데이터는 AWS S3 저장 기준이며, 사용자 옷장 삭제와 함께 공통 이미지를 삭제하지 않습니다.
- `CLOTHES.season`은 공통 옷 정보이며, 옷 등록 시 선택한 뒤 생성된 옷의 계절은 변경하지 않습니다.
- `CLOTHES.gender`는 공통 옷 정보의 대상 성별 code이며, 등록/수정 또는 초안 확인 화면에서 선택·확정할 수 있습니다. 목록/추천 카드의 일반 표시명이나 필터 UI로는 사용하지 않습니다.
- 사용자별 피드백, 즐겨찾기, 보유 상태는 사용자별 데이터로 관리합니다.

## 데이터 생성

| 이벤트 | 생성/변경 데이터 |
| --- | --- |
| 사용자 가입/온보딩 | `USERS`, `SOCIAL_ACCOUNTS`, `WARDROBES`, `OUTFIT_BOOKS`, `USER_STYLES` |
| 사진 기반 옷 등록 | `CLOTHES`, `CLOTHING_COLORS`, `CLOTHING_STYLES`, `WARDROBE_CLOTHES` |
| 구매내역 기반 옷 등록 | `CLOTHES`, `CLOTHING_COLORS`, `CLOTHING_STYLES`, `WARDROBE_CLOTHES`, 구매내역 캡처 분석 데이터 |
| 외부 상품 저장 | `CLOTHES`, 외부 출처 정보, `WARDROBE_CLOTHES` |
| 코디 저장 | `OUTFITS`, `OUTFIT_ITEMS`, `OUTFIT_STYLES` |
| 룩피드 게시 | `FEED_POSTS`, `FEED_POST_IMAGES` |
| 추천 싫어요/제외 | `RECOMMENDATION_FEEDBACKS`, `USER_STYLES.feedback_weight` |

## 옷 삭제 기준

사용자가 옷장에서 옷을 삭제할 때의 기준입니다.

| 데이터 | 처리 |
| --- | --- |
| `WARDROBE_CLOTHES` | 사용자 옷장 연결 제거 또는 비활성화 |
| `CLOTHES` | 유지 |
| `CLOTHING_COLORS` | 유지 |
| `CLOTHING_STYLES` | 유지 |
| 공통 이미지 | 유지 |
| `CLOTHES.season` | 공통 옷 정보와 함께 유지 |
| `CLOTHES.gender` | 공통 옷 정보와 함께 유지 |
| 사용자별 즐겨찾기/사이즈 | 사용자 연결과 함께 제거 또는 비활성화 |

삭제 API 구현이 `CLOTHES`를 직접 삭제하면 이 문서 기준과 충돌합니다.

## 추천 피드백 보존

- 추천 싫어요와 추천 제외는 사용자별 피드백입니다.
- 추천 제외는 해당 사용자의 추천 후보에서 영구 제외하는 기준으로 유지합니다.
- 추천 피드백은 다른 사용자 추천에 영향을 주지 않습니다.

## 룩피드 데이터

- 피드 게시글은 숨김 상태와 삭제 시점을 관리할 수 있습니다.
- 댓글은 삭제 시점을 기록할 수 있습니다.
- 좋아요, 댓글, 대댓글, 팔로우는 사용자별 상호작용 데이터입니다.
- 별도 피드 저장 기능은 요구사항 기준에서 제외되며, `FEED-004` 좋아요가 저장 역할을 대체합니다.
- 피드 이미지는 게시글 이미지 데이터로 관리하며, 게시글 삭제 정책과 함께 검토합니다.

## 사용자 탈퇴

현재 문서 기준에서는 사용자 탈퇴 시 아래 원칙을 우선합니다.

- 사용자 상태를 비활성화하고 탈퇴 시점을 기록합니다.
- 탈퇴 이력이 없는 활성 사용자의 `USERS.withdrawn_at`은 `NULL`로 둡니다.
- 탈퇴 시점부터 30일 동안은 탈퇴 철회와 계정 복구 가능성을 위해 회원별 개인정보와 사용자별 데이터를 보관할 수 있습니다.
- 30일이 경과하면 스케줄러가 탈퇴 계정의 개인정보성 필드를 삭제 또는 익명화하고, 소셜 계정 연결, 사용자 스타일, 사용자 외부 링크처럼 회원에게 직접 연결된 보조 데이터를 삭제합니다.
- 공통 옷 정보는 삭제하지 않습니다.
- 공통 옷 정보, 상품 정보, 카탈로그 분류 결과처럼 추천 품질 향상에 필요한 서비스 데이터는 회원을 식별할 수 없도록 분리, 익명화 또는 비식별화한 뒤 유지할 수 있습니다.
- 옷장 연결, 추천 피드백, 피드/댓글 등 서비스 데이터는 FK 무결성, 서비스 품질, 분쟁 대응, 부정 이용 방지 필요성을 고려해 삭제, 비활성화, 익명화 또는 비식별화 범위를 기능별로 결정합니다.
